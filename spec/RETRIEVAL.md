## 2. 输入

`EvidenceRequest` 由已经理解当前任务的模型角色提出，只包含：

- 请求与任务身份；
- 当前角色；
- 需要核对的定位问题；
- 可选目标作品；
- 可选逐字目标；
- 少量主题提示；
- 返回数量上限。

`exact_quote_targets` 按逐字连续子串定位，不理解“甲与乙相反”之类逻辑改写。
调用者只写预期在正文中连续出现的原文字串；字形、夹词或异文不确定时，改用
短而确定的连续片段并配合 `topic_hints`。一次 `not_retrieved` 只表示当前请求
未命中，不能反推正文不存在；只有未命中会改变当前结论边界时，模型才在职责
正文和最终结果中自然说明缺失，不把内部未取回编号继续传递。

证据服务不得接收或推导诊断、方义、药物职责、证明方向、图形或最终答案。

## 3. 定位与回读

1. 调用卡形成候选作品；
2. 进程内 Markdown 索引定位候选位置；
3. 命中后重新打开 `kb/texts/` 中的唯一正文；
4. 核对正文 SHA、行号、锚点和逐字摘录；
5. 返回证据状态、异文候选和跨书相关候选；
6. 不判断候选支持、反对或如何进入结论。

若正文段紧邻下一同级标题，Markdown 层级不足以唯一证明它属于前一标题。定位器
不根据段落中的方名或医学语义猜测归入下一标题，而是保守移除前一兄弟标题，只
保留双方共同的父级范围；行号、锚点、正文和 SHA 不变。具体篇章关系仍由模型
结合原文判断。

进入模型上下文的内容由宿主从返回结果中选择。应提供回答当前问题所需的句、
分句或短注释单元，以及典籍名称、`kb/texts/` 文档路径和行号；不得把内部
`evidence_id`、未经选择的超长原行、整章或整部典籍直接塞入上下文。
Skill 的规范医学记录同样只保存所选短原文及文档锚点；每个不相邻单元保持
独立来源项。定位器返回的物理整行和内部身份只留在证据结果文件中供回读，
不能重新进入对话或后续 H5。

## 4. 证据状态

- `complete`：当前目标在登记正文中完整取回；
- `fragment`：正文或目标本身存在明确残缺；
- `conflict`：来源之间存在实质冲突，服务不裁定；
- `not_retrieved`：当前检索没有取回目标原文。

模型泛化不属于直接证据。未取回时可以由模型基于预训练知识继续分析，但必须按产品口径标明来源边界，不得伪造经典出处。

## 5. 调用权

证据服务返回结果继续保留：

- `work_id`；
- 证据类型；
- 调用权角色；
- 来源路径；
- 标题层级与锚点；
- 起止行；
- 摘录与 SHA；
- 语料快照。

这些字段不等于全部进入医学记录。来源组编号不决定采用关系。具体典籍职责和
三条证据主路以 `THEORY_CORE.md` 与当前角色提示词为准；模型决定是否采用、
限制或继续取证，选择器只把短原文与可读文档锚点交给模型。

## 6. 回归范围

当前回归验证：

- 18 张调用卡覆盖清单且不夹带原文；
- 正文 SHA 和路径真实；
- 直接引文逐字回读；
- 紧邻下一兄弟标题的正文不误继承前一兄弟标题；
- 正文与编辑说明隔离；
- 完整、残文、未取回和跨书候选不混淆；
- 请求和结果的越权字段被拒绝；
- 活动证据包不导入旧 `gem_kernel`、`gem_runtime` 或 `legacy/`。

旧三代理验收账本与两个流程探针已移入 `legacy/v2/`。它们验证的是上一版验收组织，不是证据行为，因此不再作为活动测试。

## 7. 命令

```bash
python3 -B tools/retrieval.py validate
python3 -B tools/retrieval.py index
python3 -B tools/retrieval.py query --input /path/to/request.json
python3 -B tools/test_retrieval.py
```

真实 Skill 验收时还要在最终作品中展开来源并由使用者核对；确定性回归不能代替中医语义评审。
