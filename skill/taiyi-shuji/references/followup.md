# 同案复察运行参考

本文件只服务 `followup`。

## 激活与继承

复察只接受用户或简单病例状态明确激活的 `patient_record`。先追加当前可用事实
的完整快照，保存新 `turn_id` 与同案上一正式轮次 `parent_turn_id`，不按症状、
方名或文字相似度猜病例。

用 `scripts/case_record.py snapshot` 从明确父轮及其正式结果生成一次
`case_snapshot`，并与当前权威输入共同冻结。制包按职责裁剪：R0 只得到父轮最终
R0 纵向摘要；R1 得到父轮最终 R1 历史判断、上一结果和三日预测；R2 得到上一
实际／正式方、结果、三日与实施边界；红方得到这份有限快照。父轮完整原话、
calls、完整来源、候选／沙盘方、完整角色正文、红方与 Stage C 过程都不进入。
上一轮判断不得升级为当前事实或预定结论；父轮变化时当前尝试失效并重新冻结。

## 主链与红方

先由模型逐项做上一轮预测—本轮实况对照。宿主随后在同一上下文依次完成 R0、
R1、R2：R0 说明本轮变化的一气、阴阳、实质相关的五行方向、《周易》可能对应
关系、时位和变化范围，并依据父轮最终 R0 摘要重新判断原关系是延续、转变还是
已经不适用，不
机械沿用原卦；R1 直接取得完整 R0，以同案父轮和本轮变化为事实边界，从人体气化、
六经八纲、脏腑经络、病势与方证中选择实质相关的关系重新形成候选并回验。R0 已
形成五行方向时，把实际采用的医学转译写进核心证机，不展开机械五行清单；
R2 直接取得完整 R0 与 R1，判断守方、调整、转方或退回重辨。每层只装载共同
指令、当前角色指令、冻结权威输入、按职责裁剪的病例快照、完整上游正文和当前采用的
短原文，不生成任务卡或交接摘要。R2 保留全部显式方剂身份和顺序，只展开真正
影响治法结构且在限定理论范围内能够成立的药物或药组。

主体形成后必须调用隔离红方。红方使用不继承宿主对话和主体过程的干净上下文，
只取得同案有限病例快照、本轮不可变输入、完整 R0—R2、候选结果、相关方剂与已选
短原文；宿主不预选攻击重点或预期问题。红方独立攻击串案、方向未定被强定、跨层转译
断裂、预测冒充实况、历史方覆盖和未经重辨的 R2。只有实质冲突时宿主综合一次；
仍未解决则保留意见
或最小补问，不形成正式建议。

模型推理是主线。药性与用药指导只按《本草经集注》《神农本草经》
《辅行诀脏腑用药法要》判断；范围内不能成立的单味职责保持待核，不用后世药性
知识补全，也不采用十八反和十九畏。只有直接归典或来源争议
会改变判断时才定位少量短原文；模型输入不含内部证据编号和哈希。每个职责只
装入 `select_evidence.py` 选择包中的当前来源数组，红方与必要 Stage C 才接收
主体实际采用来源并集；不手写来源身份，也不复用累计来源文件。

## 结果与输出

复察不会自动要求加水量、煎取量、服用时点或长期用药细目；只有这些信息会改变
当前对象、方剂结构，或用户明确要求现实详细建议时才在分析前补问。其余未知项
进入边界或后续观察。

新的 Day 1、Day 2、Day 3 都使用 `followup_prediction`，共同前提对应本轮更新
后的 R1／R2；本轮已经发生的改善或加重不得再次写成预测。

医学职责完成后，把父轮身份、权威输入快照、`sources`、真实调用、完整角色
正文、相关方剂与 outcome 一次交给 `scripts/commit_analysis.py`；制包与提交均
使用 R0 前生成的同一 `--input-lock` 和 `case_snapshot`。提交失败不绑定本轮，
也不提交半成品结果。提交成功后在同一宿主上下文形成审计后最终 R0／R1 纵向摘要
和前后变化，再用 `scripts/case_record.py bind-analysis` 绑定当前轮次；不另启模型。
用 `scripts/render_dialogue.py` 输出完整阶段
正文、红方、必要 Stage C、预测—实况对照、新结论、三日预测、来源与补问。
最终宿主消息逐字使用 `outcome.summary` 并链接阅读版，不另写医学内容。H5 与
图像仅在用户针对当前正式结果明确要求后生成；父轮或更早轮次的可视化请求不
自动延续。
