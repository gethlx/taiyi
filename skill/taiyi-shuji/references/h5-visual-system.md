# H5 视觉系统与生成方法

本文件固化 2026-08-02 已确认的患者向 H5 视觉基线，并说明如何把它用于不同
R0 结果。病例内容不是模板；可复用的是生成语法、图形原语和材质资产。

## 一、从最终稿反推的生成链

```text
committed_analysis
  → 已校验的媒介中立纯净版 presentation_projection
  → 决定模块顺序与受控展示文案的 presentation_story
  → 图形原语 visual_primitive_selection
  → R0 有界适配 r0_adapter
  → 报告专属无字图像
  → 通用 H5 壳与 SVG 组装
  → 内容守恒、移动端和视觉验收
```

这条链有两处不可自动猜测：完整分析到纯净版的语义收敛，以及纯净版到图形关系
的医学语义整理。前端只消费明确节点、连线、职责群和观察信号，不用关键词、药性
表或五行固定映射重新推理。

纯净版标准见 [`presentation-projection.md`](presentation-projection.md)。本文件不再
重新提炼患者理解任务或生成第二套医学内容；同一纯净版供 H5 与图片并列使用。
标题、标签、图注和卡片正文可以为屏幕阅读而压缩、拆分或改成标签，但必须保留
原字段映射，不得改变事实、关系、状态和边界。

## 二、患者向稳定骨架

| 顺序 | 默认模块 | 患者获得什么 | 首选图形 |
|---|---|---|---|
| 首屏 | 报告标题与核心关系 | 这份报告讲什么、关系主轴是什么 | 3—4 节点关系带＋R0 主题图 |
| 01 | 作用总览 | 当前最重要的结论 | 关系拓扑图 |
| 02 | 事实依据 | 哪些事实支持判断、哪些尚未确认 | 多源汇入图＋事实清单 |
| 03 | 核心证机关系 | 总体关系如何转为辨证／条件证机 | 路径图＋R0→R1 专业判断桥 |
| 04 | 治法结构 | 治疗方向如何共同作用 | 中心辐射／主辅制约图 |
| 05 | 方药协同 | 各药群承担什么职责 | 药群网络＋无字植物素材 |
| 06 | 观察要点 | 哪些变化相合，哪些提示反向 | 正向／反向双轨时间图 |
| 07 | 适用边界 | 已支持与待确认在哪里分界 | 边界重叠图＋复核回执 |

模块按真实内容存在性增删。纯方剂的“事实”是组成、剂量、炮制和煎服，不是患者
症状；没有正式三日条目就不画疗效曲线。经典解释通常弱化治法、方药和观察。

## 三、内容层规则

- H1 为“对象＋判断／分析类型”的陈述句；品牌不占主标题。
- H2/H3 使用“作用总览”“事实依据”“核心证机关系”“治法结构”“方药协同”
  等报告语言，不使用“为什么会这样”“治法落在哪里”等问句。
- 首屏只保留 H1、核心关系带、关系图例和品牌／报告类型，避免重复摘要占满首屏。
- R0 保留一段收敛后的专业关系原文；R1 保留辨证分型或条件性证机原文；二者之间
  用视觉承接和患者解释连接，不展示角色工作过程。
- 红方只在真实执行后显示结果回执；修复前内容、攻击过程和内部轮次不进入页面。
- 专业结论、药名剂量、炮制煎服和边界不能写进生成图片。

## 四、通用视觉母体

已确认的视觉语言是“当代玉简＋绢本／丝纸＋矿物颜料”：

- 左侧玉质章节轨道建立纵向秩序，右侧温润绢本承担阅读；
- 深玉 `#315f53`、暖绢 `#f4efe2`、赭金 `#b78a45` 为稳定母体；
- 青瓷绿、矿物蓝灰、朱砂只作受控节点与状态强调；
- 宋体用于 H1、H2 和专业原文，无衬线用于正文、图例和数据；
- 金线、矿物晕染、药材标本提升精致度，但不使用廉价卷轴、祥云或八卦满铺；
- 确认／条件／未知使用实线／虚线／点线和文字共同编码，不随 R0 换色。

通用材质只提供品牌连续性。报告的冷暖、构图中心、流向和张力由 R0 适配，但不
改变字体层级、章节顺序、风险可见性和状态语义。

## 五、R0 适配器

只从最终 R0 提炼下列有限参数：

| 参数 | 候选值 | 页面影响 |
|---|---|---|
| `visual_salience` | 弱／中／强 | R0 图占比和首屏视觉权重 |
| `topology` | 中心／边缘、上下／内外、单轴／多轴、环路／开放路径 | 主视觉和关系图构图 |
| `dominant_vector` | 升／降／内收／外展／往复／交错／无主向 | 流线与动效方向 |
| `openness` | 开／阖／枢转及相对关系 | 门径、枢轴和转折结构 |
| `rhythm` | 连续／间歇／脉冲／缓进／多阶段 | 线条节奏和渐显方式 |
| `tension` | 平衡／牵制／壅滞／松解／未定 | 留白、节点距离和张力 |
| `density` | 疏／中／密 | 构图密度；不表示病情程度 |
| `emphasis` | 一个核心关系 | 首屏中心节点与局部强调 |
| `accent_direction` | 品牌色域内的局部倾向 | 小面积冷暖变化 |
| `metaphor_boundary` | 允许／禁止隐喻 | 防止卦象、人体和器物过度解释 |

五行、卦象只有在最终 R0 明确成立且对结论实质相关时才进入主视觉。不得把五行
固定映射为脏腑、证型、药物、治法或颜色皮肤；医学翻译必须来自最终 R1。

## 六、图形原语的选择

1. **汇入图**：多个已确认事实共同支持一个判断；不得把未知项画成输入证据。
2. **关系拓扑图**：展示相互作用、条件作用和待确认关系；节点与边必须来自纯净版。
3. **路径图**：展示有明确先后或承接的证机链；无可靠顺序时改用拓扑图。
4. **中心辐射图**：展示多个治法或药群围绕一条主轴协同；不能制造君臣层级。
5. **主辅制约图**：展示主轴、兼顾和制约；只有正文明确时使用。
6. **时间双轨图**：并列呈现相合变化与反向信号；不把观察方向画成量化疗效。
7. **边界图**：区分当前支持、仍待确认和重叠范围；适合结论边界与补问。
8. **专业判断桥**：R0 原文→关系图→R1 原文→患者解释，避免专业判断与视觉割裂。

每个重要图都要有可读标题或图注，并能回指纯净版中的明确语义。图形不是把文字
放进圆圈；空间、连线、方向和分组本身必须承担解释。

## 七、图片资产生成

每份报告最多先规划两类生成图，再按内容需要增加：

### R0 首屏主题图

提示词由通用母体、R0 五维参数和构图槽位组成。要求：横向背景、中心留出关系带
和题签可读区、无文字、无符号堆砌、无诊断标签。画面表达空间与动势，不直接画
成已确诊的身体病灶。

### 方药素材图

只在存在方药职责群时生成。要求：植物标本／药材静物、俯视或浅景深、背景透明
感或低对比、无文字；按职责群提供可被 SVG 圆形节点裁切的素材。药群名称和具体
药味由 HTML/SVG 覆盖。

报告专属图不要进入 Skill 默认资产。Skill 只保存通用绢本材质、组件和经过确认的
图形代码；样例图片只作为设计证据，不作为下一份报告的风格输入。

## 八、资产调用

`assets/h5-report/` 中：

- `VisualReportShell.tsx`：无病例内容的数据驱动 React 外壳和 SVG 原语；
- `taiyi-visual-report.css`：已确认的玉简／绢本排版、材质、状态和移动端规则；
- `silk-jade-surface.webp`：可直接复用的通用背景材质；
- `asset-manifest.json`：生产资产、动态资产和样例证据的边界。

新项目先执行：

```bash
python3 -B skill/taiyi-shuji/scripts/scaffold_visual_h5.py \
  --output-root /absolute/path/inside/project
```

脚本只复制通用资产，不生成报告内容，也不覆盖已有文件。随后由当前任务将纯净版
映射成 `H5ReportViewModel`，把专属图片放入 `public/assets/taiyi-h5/`，再完成构建。
使用 `scripts/validate_h5_view_model.py` 校验纯净版哈希、同一 run/result 绑定、关键
不可变文本复制、核心关系结构、节点范围、连线索引和可选模块结构；适配文案通过
`presentation_story` 的来源字段追溯，医学语义仍由当前任务复核，不能以结构校验替代。

## 九、交付验收

- 两个分析结果是两个 URL／两个 H5，不使用病例切换 Tab；
- 393×852 视口首屏可读，头部约 234px，不被状态栏或复杂背景遮挡；
- 题签、节点、图例和署名均有独立半透明绢纸承载层；
- 页面至少以 SVG 表达关系、机制、治法、方药、观察和边界中的适用部分；
- 生成图是图表组成或主题背景，不是正文旁的装饰配图；
- 长药味、未知项、最小补问和来源按需展开；
- 无横向溢出，键盘焦点可见，`prefers-reduced-motion` 生效；
- 最终截图与同一份投影逐项核对：不可变字段逐字一致，可变字段可追溯且语义守恒；
  保存首屏、核心机制、方药和完整长页证据。
