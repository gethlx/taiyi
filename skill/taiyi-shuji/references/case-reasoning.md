# 实际病例运行参考

本文件只服务 `case_reasoning`。

## 病例事实

先在个人病历追加本轮事实完整快照，保存用户原话、唯一 `case_id` 与本轮
`turn_id`。明确陈述及明确更正进入已确认事实；方向、程度、时点或用户自己不能
确定的内容进入含混事实，不替用户选定。用户主动提供的体系外信息留在
`external_context`，医者既有判断留在 `clinician_opinions`；两者都不是中医
事实或本轮预定结论。只要求记录、查看或纠正时不进入医学主链。

病例可以没有方名或显式组成。候选方与正式详细建议身份分离；实际提出候选方
时另存为 `candidate` 方。未解实质冲突时不得产生正式建议或正式方身份。

## 主链与红方

宿主在同一上下文依次完成 R0、R1、R2。R0 独立说明一气、阴阳、实质相关的
五行方向、《周易》可能对应关系、时位和变化范围，不逐项复述具体症状、方药或
实施信息，也不给 R1 下判断指令；R1 直接取得完整 R0，从本轮事实、人体气化、
六经八纲、脏腑经络、病势与方证中选择实质相关的关系形成候选并回验；R0 已形成
五行方向时，把实际采用的医学转译写进核心证机，不展开机械五行清单，并保留不能
纳入的事实；R2
直接取得完整 R0 与 R1，承接治法、方证、方药结构和实施边界。病例角色 packet
读取当前确认／含混事实、对象和方剂，不装入完整原话中的隔离外部信息；完整
`raw_text` 仍保存在病历和正式分析。每层只装载共同指令、当前角色指令、冻结
权威输入、完整上游正文和当前采用的短原文，不生成
任务卡或交接摘要。R2 保留全部显式方剂身份和顺序，只展开真正影响治法结构且
在限定理论范围内能够成立的药物或药组。

主体结果形成后必须调用隔离红方。红方使用不继承宿主对话和主体过程的干净上下文，
只取得完整不可变输入、R0—R2、候选结果、结果侧方剂及已选短原文；宿主不预选
攻击重点或预期问题。红方独立攻击串案、事实方向、跨层证机、方药身份、实施边界
与预测条件。只有红方提出会改变结论的实质冲突时，宿主综合一次；仍未解决则使用
`reserved_opinion` 或 `facts_or_evidence_insufficient`，不能包装为正式详细建议。

模型预训练知识与中医推理是主线。药性与用药指导只按《本草经集注》
《神农本草经》《辅行诀脏腑用药法要》判断；范围内不能成立的单味职责保持待核，
不用后世药性知识补全，也不采用十八反和十九畏。只有直接
归典或来源争议会改变结论时才取回少量短原文；模型看到作品名、路径、行号和
短原文，不看内部证据编号与哈希。来源数组直接使用 `select_evidence.py` 的选择包，
不手写来源身份。每个职责只装入当前采用的临时来源数组，
红方与必要 Stage C 才接收主体实际采用来源的并集，不复用累计来源文件。

## 结果与输出

病例分析不因任务身份自动要求加水量、煎取量、服用时点或长期用药细目；这些信息
只有确实改变当前对象、方剂结构或用户明确要求现实详细建议时才在分析前补问。
其余未知项进入边界或后续观察，不阻断主体辨证。

事实与证机足够且没有未解实质冲突时，可以输出 `r2_pending_physician_review`，
并把详细建议标为“待医师复核”。Day 1、Day 2、Day 3 都使用
`case_prediction`，写明成立前提、应观察的中医证候变化及不符时的回退边界。

医学职责完成后，把权威输入快照、`sources`、真实调用记录、完整角色正文、
结果侧方剂与 outcome 一次交给 `scripts/commit_analysis.py`；制包与提交均使用
R0 前生成的同一 `--input-lock`。提交失败时不导入
病例状态，也不提交半成品结果。用 `scripts/render_dialogue.py` 输出完整阶段
正文、红方、必要 Stage C、结论、三日观察、来源与补问；最终宿主消息逐字使用
`outcome.summary` 并链接阅读版，不另写医学内容。H5 与图像仅在用户针对当前正式
结果明确要求后生成，旧请求不延续到新病例或新轮次。

提交成功后，在同一宿主上下文把审计后最终成立的 R0、R1 各压缩为一个纵向摘要，
连同未解边界写入 `final-evolution.json`，再用
`scripts/case_record.py bind-analysis` 绑定当前轮次。不另启模型；完整职责正文继续只留在正式分析。
绑定失败不撤销分析，可以重试绑定。
