# 经典解释运行参考

本文件只服务 `classic_interpretation`。

## 输入与职责

原样保存用户输入。主对象可以是原文片段、概念、理论问题或跨书关系；引述、
比较与参考对象不能覆盖主对象。实质歧义无法可靠判断时，只问一个最小问题。

用 `scripts/load_role_prompt.py --role r0` 只装载共同指令与 R0 指令。R0 先说明
一气统摄和明确的阴阳关系，实质相关时辨明五行的盛衰、生克或周流方向，
再给出一个或少量《周易》可能对应的卦象、卦辞或爻辞关系、对应理由与成立范围；
按实际需要展开时位、变化、上下内外及动静往来。卦象和五行只作结构与变化参照，
不直接等同病名、证型、脏腑、药物或治法。涉及五行、消息、升降反复、火候或
时序时，按需使用《周易参同契》。

经典解释通常由宿主完成 R0 即可。只有主体结论本身存在值得独立攻击的实质
冲突时才启用隔离红方；若红方提出会改变结论的冲突，宿主只综合一次。

## 取证与来源

模型预训练知识、知识涌现与关系泛化是主线。仅在用户要求原文或出处、结论要
直接归属于经典、调用权或异文有疑义，或短原文会实质改变解释时检索。没有新增
价值时沿用已经定位的少量材料，不为数量完整逐项检索。

检索使用 `tools/retrieval.py query`。模型确定要核对的短语后，再用：

```bash
python3 -B scripts/select_evidence.py \
  --result /absolute/path/to/evidence-result.json \
  --evidence-id EV-... \
  --contains "要核对的短语"
```

`--evidence-id` 只是检索服务内部定位参数。角色输入与正式结果只接收选择包中的
语义完整且连续的短原文、作品名、`kb/texts/` 路径和行号；不接收证据编号、
哈希、整章或未经选择的超长原行，也不把不连续片段拼成一条经典主张。把选择包
中的 `sources` 数组作为当前职责临时来源，通过 `build_role_packet.py` 的
`--current-role-sources` 传入，并同时传 R0 前生成的 `--input-lock`；不要沿用其他职责
或上一轮的累计来源文件。解释结论不得伪装成经典逐字主张，也不反复添加模型
来源免责声明。

## 输出

向用户完整呈现本任务实际形成的 R0 正文，并按需附少量来源、适用范围与一个
最小补问。执行过程中可简短说明正在定位原文或解释关系，但不另调用模型生成
交接摘要。完成后用同一规范记录的全文渲染总结性文字；H5 与图像仅在用户明确
要求后另行提供。
